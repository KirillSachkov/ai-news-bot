Из 7 141 истёкшей записи 7 137 не получили вердикт. Проверенные примеры показывают потери на эвристическом пороге и при ограниченном бюджете оценки. Долю каждой причины по всей истории не измеряли. Истечение само по себе не доказывает ценность записи. Фильтр пропускает немало общего информационного шума.

У 8 283 отказов редактора преобладают категории `other` (5 638), `industry` (834), `safety` (618), `tool` (354). Это категории вердикта, а не стандартизованные причины отказа. Полного достоверного счётчика смысловых причин нет; автоматическую классификацию отказов моделью не запускали.

Среди отправленных: `safety` 74, `release` 53, `tool` 46, `industry` 40, `breakthrough` 22, `viral` 11, прочие размеченные 6. У 104 старых отправок нет нынешней рубрики, а ещё 3 отправки не имеют вердикта. Всего получается 359. Поэтому доли всего периода нельзя выдавать за текущий редакционный профиль.

Скользящие сутки отличаются от календарного дня. За период с 14 сентября до снимка отправлены 252 сообщения; медиана возраста публикации при доставке 66,4 минуты, максимум 332,4 минуты. Полная история содержит старые аномалии дат, включая публикации из будущего; они не описывают текущую задержку.

Оценки за всю историю: 17 полезных, 17 отрицательных. После 14 сентября: 8 полезных, 0 отрицательных. Выборка мала и добровольна, поэтому процент точности по ней не вычисляем. Нынешние находки владельцу подходят; сокращать сильные рубрики по старым отрицательным оценкам оснований нет.

Журнал содержит 2 484 полных обхода. Медиана составляет 89,1 секунды, p95 составляет 125,8, максимум 811,7. Значение p95 означает, что 95% полных обходов уложились в указанную длительность. Быстрых обходов 6 479: медиана 24,7, p95 37,3, максимум 466,9 секунды. Длительность включает редактора; большой хвост задержек нарушает ожидаемую регулярность. Новая телеметрия показывает длительности источников, итог цикла, счётчики редактора и превышение интервала быстрой полосы.

Учёт модели за весь период: 15 447 вызовов, 67 337 982 входных и 2 476 517 выходных токенов. Это фактический старый расход, включая повторные проверки. Стоимость по счёту и скидки кэша недоступны. Новые платные API не подключены. Число вызовов ограничено прежним бюджетом; длительность дополнительно ограничена. Изменение задания модели меняет объём токенов, поэтому прежнюю стоимость не обещаем.

Этот cooldown растёт экспоненциально, до часа. Запись здоровья показывает последнюю проверку, количество, дату публикации, длительность и ошибку; `/sources` разбивает длинный ответ на сообщения.

## Подтверждённые дефекты и исправления

| Воспроизведение до исправления | Результат после исправления |
|---|---|
| `/digest` выполнял долгий сбор в потоке команд | Сбор передан фоновому потоку; `/pause` и `/mute` учитываются при завершении |
| `/digest` или первый полный сбор, затем `/pause`, затем результат фонового сбора отправлял карточку | Последняя пауза запрещает отправку; регрессионный тест с поддельным Telegram |
| Три уже оценённых практических кандидата занимали резерв | Резерв выбирает только неоценённые записи без исчерпанного лимита ошибок |
| Ошибки модели не расходовали лимит попыток | Все попытки входят в прежний предел; HTTP 401 не штрафует отдельную запись |
| Шесть сломанных ответов проверки повтора блокировали седьмой | Две ошибки конкретной записи исчерпывают её лимит; сетевые ошибки сохраняют непроверенный результат и очередь пробует других |
| `duplicate_of: garbage/-1/999/bool/float` считался отсутствием повтора | Ошибка валидации; карточка ждёт проверенный ответ |
| Неспешное HTTP-тело и curl при остатке меньше секунды превышали общий предельный срок | Оставшееся время пересчитывается на каждом чтении, включая тело ошибки HTTPError; ответ сервера закрывается |
| Даты из будущего проходили свежесть | Допуск 15 минут; будущая запись за пределом допуска не доставляется |
| Telegram/RSS выбирали первые записи до сортировки | Сначала разбор и сортировка по реальной дате, затем ограничение количества записей |
| YouTube и Atom с вложенной HTML-разметкой теряли описание | Добавлено описание из медиаэлемента и текст вложенного XHTML |
| GitHub rising заменял дату создания текущим временем | Сохраняется реальная дата создания (createdAt); обнаружение показывается отдельно |
| Зрелые HF models отсеивались как старые | Конечное окно обнаружения 48 часов; повторный опрос не обновляет его |
| Рост 10/30/30 повторно оживлял старую запись | Новый сигнал требует дополнительного роста после прошлого сигнала |
| Новый измеренный рост проходил отбор, но немедленно истекал по старой дате обнаружения | Срок записи в очереди и её порядок учитывают дату измеренного роста |
| Dry-run менял баллы, статусы и кэш в исходной базе | Копия базы SQLite создаётся до миграции; изменения остаются в копии |
| Dry-run обходил проверку повтора по сохранённым результатам | Сохраняются свежесть, бюджет и проверка повтора; запуск без модели явно показывает старый профиль |
| Длинная карточка обрезалась внутри HTML | Обрезаются поля до экранирования и разметки |
| Успешный HTTP с плохим JSON не учитывал расход токенов | Токены записываются до интерпретации JSON |

Общий предельный срок ограничивает чтение тела, повторные попытки, ожидания и запасной запрос через curl. Сетевая библиотека Python urllib не даёт строгой общей гарантии для поиска адреса по имени, переадресаций и чтения заголовков ответа. Независимый контрольный опрос ограничен отдельным процессом 50 секунд; обычный фоновый сбор не получает такую полную гарантию. Остаточный риск виден по длительности цикла и превышению интервала и требует другого HTTP транспорта, если хвост сохранится.

## Изменение отбора и сравнение до/после

Личный практический интерес Кирилла имеет самостоятельный вес. Каналы-ориентиры сохраняются как подтверждение, а их записи не отправляются. Три места для практических находок берутся из прежних 20 вызовов полного и 6 быстрого обхода; дополнительный лимит попыток не добавлен. Эвристический порог практических находок 2,5 сохраняет фильтрацию; ручная настройка не гарантирует каждую находку.

Новость имеет окно 6 часов. Практическая публикация, находка проекта/модели и измеренный рост имеют конечное окно 48 часов. Карточка различает реальную дату публикации, обнаружение и рост. Обнаружение старого объекта и рост сами по себе не открывают срочную полосу.

Рост требует двух наблюдений минимум через час. У модели HF измеряются отметки «нравится» (likes), у HN баллы обсуждения, у GitHub звёзды. Для каждой площадки одновременно нужны абсолютный прирост (HF +5, HN +10, GitHub +20) и минимум 20% относительно исходной точки. Например, рост HN с 10 до 30 баллов через час проходит оба порога, а с 100 до 110 не проходит 20%. Наблюдения хранятся 14 дней. Повторный сигнал возможен через 6 часов и только при дополнительном росте. Это измерение интереса, не доказательство качества или нового релиза. Одно число stars/likes и количество копирующих публикаций ростом не считаются.

Повторный прогон без сети и модели использует одинаковую исходную базу baseline.db и полные ответы контрольного опроса. Время оценки зафиксировано на `2026-10-07T10:55:00+00:00`.

## Review, выпуск и откат

Независимый `news-review` обнаружил семь исходных дефектов, затем два дефекта финального набора изменений и добавил 13 регрессионных тестов. Автор основного кода исправил их. Финальная независимая проверка всех изменений и отчёта проводится перед выпуском; её результат и применение будут записаны отдельным протоколом в этом каталоге и в Issue.

Ожидаемый простой при применении: 5–15 секунд, systemd допускает остановку до 20 секунд. Перед остановкой сохраняется новая согласованная SQLite-копия и код. Применяется проверенная версия кода; существующее состояние не заменяется. Проверяются версия, systemd, полный и быстрый обход, здоровье новых источников, лимиты и сохранность оценок, весов и записей отправки.

Откат: остановить сервис, вернуть код к `4621e3c`, запустить сервис. Новые таблицы и столбцы добавляются без удаления старых, старый код их игнорирует. Текущую базу следует сохранить. Восстановление старой копии потеряет новые оценки и записи отправки. Бэкап базы нужен только для отдельного восстановления при повреждении, после сохранения актуальной копии.

Владелец не должен принимать новое решение для этого выпуска. Лимиты согласованы, новые режимы или расписание дайджеста не добавлены. Платный X API, whitelist-письма и вход не выполнялись. Ограничения: короткая X-лента, 429 Reddit, четыре X-зеркала, редкие авторские RSS, резерв HF Spaces, непроверенная будущая точность нового редакционного профиля.

## Как повторить проверку

Рабочая папка для команд ниже находится в корне checkout `/Users/dev/Work/Content/ai-news-bot`. Используй отдельную копию состояния, без `.env` и без реального Telegram. Probe сохраняет полный публичный контент. Его JSONL остаётся вне git. `unseen6h` сравнивает UID, уникальный идентификатор записи, с копией базы; финальный сбор дополнительно проверяет ссылку без параметров отслеживания и окно конкретного источника.

В примере `/PRIVATE` обозначает закрытый каталог копий, а `/PATH/ai-news-bot` обозначает новую проверяемую версию. Параметр `--offline` исключает модель, `--no-fetch` исключает сбор, а `--top 15` ограничивает показ кандидатов.

```bash
cd /Users/dev/Work/Content/ai-news-bot
python3 -m unittest discover -s tests
python3 tools/audit_probe.py /PRIVATE/probe.db > /PRIVATE/sources.jsonl
python3 bot.py --db /PRIVATE/baseline.db once --dry-run --offline --no-fetch --top 15
python3 tools/audit_replay.py /PRIVATE/old-code /PRIVATE/baseline.db /PRIVATE/sources.jsonl 2026-10-07T10:55:00+00:00
python3 tools/audit_replay.py /PATH/ai-news-bot /PRIVATE/baseline.db /PRIVATE/sources.jsonl 2026-10-07T10:55:00+00:00
```

`old-code` получают из `git archive 4621e3c`, чтобы версия коллектора отличалась, а данные оставались одинаковыми. Для точного повторения цифр используй закрытый архив исходного опроса и исходной базы. Перед и после dry-run сравни SHA256 базы. В серверной проверке он остался `9082df4df785a91e5aaa5242302b21c06c22a077a5862007e0459850fb84ff7d`.
