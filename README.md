# ai-news-bot — личный новостной бот по ИИ и разработке

Присылает в Telegram актуальные новости, анонсы и события из мира технологий и
искусственного интеллекта. Каждую новость можно оценить кнопками — бот
подстраивает отбор под тебя.

Только стандартная библиотека Python (3.9+). Никаких `pip install`, никаких
подписок и платных API: единственная необязательная платная часть — DeepSeek,
и она укладывается в бесплатный стартовый грант.

---

## 1. Быстрый старт

```bash
cd ~/ai-news-bot

# 1) токен бота
cp .env.example .env
#   впиши TELEGRAM_BOT_TOKEN=... (получить: @BotFather -> /newbot)
chmod 600 .env

# 2) узнай chat_id: открой бота в Telegram и нажми Start, затем:
python3 bot.py whoami

# 3) проверь, что источники живы
python3 bot.py check

# 4) запусти
python3 bot.py run          # или ./run.sh
```

При первом запуске бот не вываливает бэклог: он помечает всё старое как
прочитанное и пишет «Бот подключён». Дальше присылает только новое.

## 3. Живой режим и как это не спамит

Бот работает в два потока: основной держит Telegram (команды и кнопки отвечают
всегда), фоновый собирает источники. Сбор идёт на двух скоростях:

- **быстрая полоса** — около десятка источников, которые реально приносят
  новости первыми, опрашиваются каждые `fast_interval_seconds` (90 с);
- **полный обход** всех источников — каждые `fetch_interval_seconds` (15 мин).

Источник попадает в быструю полосу полем `"tier": "fast"` в `sources.json`.
Быстрая полоса дешёвая: запросы условные (ETag / Last-Modified), и неизменённая
лента отвечает `304` без тела.

Защита от спама — четыре уровня:

1. **Часовой бюджет.** `max_per_hour` (2) и `min_gap_minutes` (20). Пауза
   соблюдается и внутри одной пачки: два сообщения подряд не уйдут.
2. **Порог балла.** Всё ниже `min_score` не отправляется.
3. **Гейт свежести.** `max_age_hours` (6) проверяется в момент отбора, а не
   только при сборе. Новость, пролежавшая в очереди до устаревания, получает
   статус `stale` и не приходит никогда.
4. **Дедупликация по сюжетам.** Записи группируются в «сюжеты» по общим именам
   собственным и близости заголовков. Имена переживают перевод, поэтому русский
   и английский пересказ одного события попадают в один сюжет. Как только сюжет
   отправлен, остальные его носители помечаются `duplicate`.

**Важное приходит сразу.** Отдельный канал со своим лимитом
(`breaking_max_per_hour`, своя пауза `breaking_min_gap_minutes`, потолок за
сутки `breaking_max_per_day`). Попасть в него можно двумя путями:

- **подтверждение** — сюжет несут `breaking_min_groups` (3) независимых группы
  источников. Это и есть честная мера «об этом говорят все»;
- **вес** — балл выше `breaking_score` и событийное слово в заголовке
  (`released`, `announces`, `open-source`, `представил`…).

Устаревшее и недатированное в breaking не попадает никогда.

## 4. Как отбираются новости

Двухступенчатый отбор — это главное решение архитектуры:

```
сбор (50+ источников, две скорости, условные запросы)
  → дедуп по каноническому URL (utm-хвосты не создают дублей)
  → группировка в сюжеты  ← имена собственные + близость заголовков
  → дешёвый эвристический скоринг  ← бесплатно, по всем записям
  → шортлист (llm_min_heuristic и llm_max_per_cycle)
  → DeepSeek судит и пишет по-русски ← только по шортлисту
  → + бонус за подтверждение независимыми источниками
  → гейт свежести → бюджет / breaking → дедуп по сюжету
  → доставка + кнопки оценки
```

Почему так: эвристика бесплатна и работает по всем записям, а модель вызывается
только там, где эвристика уже видит потенциал. На типичном объёме это
10–20 вызовов в сутки.

Скоринг учитывает: вес источника, свежесть, слова-сигналы (релиз, прорыв,
покупка), сущности (OpenAI, Anthropic, DeepSeek, Qwen…), вовлечённость
(лайки, очки HN, апвоты HF) и штрафы за рекламу, вакансии, вебинары, мемы.

## Профиль интересов

Тематический фильтр живёт в `config.json` → `interests` и правится руками.
Он применяется на двух уровнях сразу, и это не дублирование:

- **`suppress` / `boost`** — дешёвый предфильтр по подстрокам. Срабатывает до
  модели и не даёт нежеланным темам съедать бюджет LLM. Совпадение подстрокой,
  без регулярок: `"ракет"` ловит ракета/ракеты/ракетных. Штраф
  `suppress_penalty` (3.0) и бонус `boost_bonus` (0.8).
- **`profile`** — текст, который подставляется в системный промпт модели. Он
  разбирает то, чего подстроки не умеют: отличает релиз лаборатории от военного
  сюжета, где модель лишь упомянута.

Текущая настройка: интересны разработка ИИ, полезный софт и технологические
новости; неинтересны военное применение, шпионаж, санкции и политика. Спорные
случаи решает правило «что технология умеет — да; кто ею злоупотребил — нет».

Замер на реальных заголовках:

| Заголовок | Эвристика | Вердикт модели |
|---|---|---|
| Yemeni militants used Anthropic AI to build ballistic missiles | 5.68 → **2.68** | `skip` 1.0 |
| Trump orders US government to cut ties with Anthropic | 4.98 (стоп-слов нет) | `skip` 2.0 |
| EU AI Act: новые требования к провайдерам моделей | — | `send` 6.0 |
| Show HN: A local, open-source version of Claude Code | 7.58 → **8.38** | `send` 8.0 |
| Unity выпустила плагин для Claude Code | 6.78 → **7.58** | `send` 8.0 |

Политику без стоп-слов ловит только модель — и это нормально: держать в
`suppress` слово «политик» нельзя, иначе под нож пойдёт и регуляторика ИИ,
которая как раз нужна.

⚠️ После правки `profile` старые вердикты надо сбросить, иначе очередь
останется разобранной по прежним правилам. Кэш LLM инвалидируется сам (хэш
профиля входит в ключ), но таблицу `verdicts` нужно почистить:

```bash
sqlite3 state/news.db "DELETE FROM verdicts WHERE nid IN
  (SELECT nid FROM items WHERE status='pending')"
```

**Обучение на оценках.** Каждое 👍/👎 сдвигает вес источника и вес ключевых
терминов этой новости. Через пару недель отбор заметно смещается в твою сторону.
Посмотреть накопленное: `python3 bot.py stats`.

## 5. X / Twitter: что работает на самом деле

X — самый дорогой источник: официальный API с февраля 2026 полностью
pay-per-use, бесплатного тира нет. Ни один канал ниже не требует аккаунта,
cookies или сессионных токенов.

**Канал 1 — майнер ссылок из Telegram (`x_miner`).** Самый дешёвый: ссылки на
посты X лежат в уже скачанных страницах Telegram-каналов, то есть запросов к X
на обнаружение — ноль. Пост гидратируется слоем контента и попадает в общий
отбор. Работает.

**Канал 2 — Bluesky (`bsky_*`).** Не обход X, а легальная замена для тех, кто
там дублируется: `karpathy`, `emollick`, `natolambert`, `arankomatsuzaki`, плюс
официальные аккаунты theverge.com, techcrunch.com, microsoft.com, github.com.
Публичный API AT Protocol бесплатный, без ключей. Работает.

**Канал 3 — зеркала (`x_user`).** Здесь остался ровно один маршрут:
`rss.xcancel.com`. Проверено вживую 11.09.2026:

| Маршрут | Что реально отдаёт |
|---|---|
| `rss.xcancel.com` | валидный RSS — но требует whitelist читалки |
| `twiiit.com` | редирект на случайное зеркало → HTML-заглушка, 403/404 |
| `nitter.privacyredirect.com` | TLS-ошибка протокола |
| `nitter.tiekoetter.com` | HTML вместо фида |
| `nitter.net` | таймаут TLS-хендшейка |

Проверены и остальные публичные зеркала: `poast`, `space`, `lightbrd`,
`kareem.one` — все за Cloudflare; `rsshub.app/twitter/...` — 404.

Мёртвые четыре маршрута **удалены, а не оставлены про запас**: каждый вызов
`x_user` стоил 31,6 секунды на аккаунт и возвращал ноль записей — больше
половины всего цикла сбора на четырёх аккаунтах. Cooldown их не спасал: он
срабатывает по коду ответа, а зеркало, отдающее HTML с кодом 200, под него не
попадает и опрашивается каждый цикл заново. Возвращать маршрут — только после
того, как его увидели работающим.

**Как включить xcancel.** Фид отвечает `200` с текстом «RSS reader not yet
whitelisted» и выдаёт ID. Нужно одно письмо на `rss@xcancel.com` с этим ID
**и причиной** — запрос без причины игнорируется, фид предупреждает об этом
прямым текстом. Готовое письмо лежит в `~/.config/newsbot/xcancel-whitelist.eml`,
отправка — `~/.config/newsbot/send-xcancel.sh`.

⚠️ **ID привязан к User-Agent.** Другой UA — другой ID, whitelist перестаёт
действовать. Не менять `FEED_READER_UA` в `newsbot/x_sources.py`.

**Слой контента (по ID поста) — решённая задача:** `cdn.syndication.twimg.com`
(собственный embed-бэкенд X) → `api.fxtwitter.com` → `api.vxtwitter.com`.
Работает независимо от того, каким каналом найден ID.

Проверено и отвергнуто: `api.fxtwitter.com/<handle>` отдаёт только профиль, без
последнего поста — как канал обнаружения не годится.

Если xcancel тоже ляжет, остаётся официальный API: ~$0.005 за чтение поста, для
4–10 аккаунтов с опросом по `since_id` это порядка $5–10 в месяц.

Никаких аккаунтов, cookies, прокси и пулов сессий — принципиально: именно за это
X судится с зеркалами, и именно на этом банят аккаунты.

## 6. DeepSeek

```bash
python3 bot.py models    # список id моделей для твоего ключа
python3 bot.py stats     # расход токенов за сегодня
```

Модель и базовая URL берутся из `DEEPSEEK_MODEL` / `DEEPSEEK_BASE_URL`.
`thinking` отключён — для классификации это лишние деньги.

Экономика: на новом аккаунте DeepSeek даёт бесплатный грант токенов; при
шортлисте 10–20 вызовов в сутки он расходуется медленно, а дальше это центы в
месяц. Без ключа бот работает на эвристике — просто без русских пересказов и
без LLM-вердикта.

## 7. Постоянная работа

### macOS (launchd) — уже установлено

Агент лежит в `~/Library/LaunchAgents/ai.newsbot.plist` и поднимает бота при
входе в систему, перезапуская его после падения.

```bash
launchctl load   ~/Library/LaunchAgents/ai.newsbot.plist   # включить
launchctl unload ~/Library/LaunchAgents/ai.newsbot.plist   # выключить
launchctl list | grep newsbot                              # статус
tail -f state/newsbot.err                                  # лог
```

`KeepAlive` настроен на `SuccessfulExit: false` — чистая остановка через
`unload` не приводит к бесконечному перезапуску, а падение приводит.

### Только cron (режим без кнопок)

Кнопки оценки требуют живого процесса (long polling), а живой режим — тем более:
`once` не держит быструю полосу. Если нужен именно cron, доставка работать будет,
но с задержкой в интервал крона:

```
*/20 * * * * cd /PATH/ai-news-bot && ./run-once.sh >> /tmp/newsbot.log 2>&1
```

## 8. Управление источниками

`sources.json` — просто JSON. Поля: `name`, `type`, `group`, `weight`,
`enabled`, плюс параметры типа (`url`, `channel`, `handle`, `limit`).

Типы: `rss`, `hn_front_page`, `hn_show`, `hf_daily_papers`,
`hf_trending_models`, `telegram_web`, `x_user`, `x_miner`, `bsky_user`.

`"tier": "fast"` кладёт источник в быструю полосу (опрос раз в 90 с вместо
15 минут). Держи её короткой: это оправдано только для лент, которые реально
приносят новости первыми.

Добавил источник — проверь: `python3 bot.py check --source ИМЯ`.
Отключить: `"enabled": false`.

Reddit `r/LocalLLaMA` подключён: раньше его `.rss` отдавал пустой ответ, на
11.09.2026 отвечает нормально. `venturebeat_ai` отключён — HTTP 429 на каждом
запросе.

## 9. Диагностика

```bash
python3 bot.py check                    # что отвечает, что молчит
python3 bot.py stats                    # состояние, веса, расход LLM
python3 bot.py xdiag                    # маршруты обнаружения X + ID для вайтлисты
python3 bot.py explain "OpenAI released a new model" --source openai_news
python3 bot.py once --dry-run --top 15  # что БЫ отправилось (ничего не шлёт)
python3 bot.py test-send                # проверка доставки
```

Частые проблемы:

- **Ничего не приходит.** Норма на старте: порог `min_score` может быть высоким
  для узкого набора источников. Посмотри `once --dry-run --top 15` и снизь
  `min_score` в `config.json`.
- **`chat_id is unknown`.** Не нажал Start в боте; сделай `python3 bot.py whoami`.
- **Источник в «молчат».** Смотри `/status`. RSS-ленты ломаются редко, зеркала X —
  регулярно; это ожидаемо.
- **Токен утёк.** `@BotFather` → `/revoke` → новый токен в `.env`.
