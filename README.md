# ai-news-bot — личный новостной бот по ИИ и разработке

Присылает в Telegram актуальные новости, анонсы и события из мира технологий и
искусственного интеллекта. Каждую новость можно оценить кнопками — бот
подстраивает отбор под тебя.

Только стандартная библиотека Python (3.9+). Никаких `pip install`, никаких
подписок и платных API: единственная необязательная платная часть — DeepSeek,
и она укладывается в бесплатный стартовый грант.

---

## 1. Быстрый старт

```bash
cd ~/ai-news-bot

# 1) токен бота
cp .env.example .env
#   впиши TELEGRAM_BOT_TOKEN=... (получить: @BotFather -> /newbot)
chmod 600 .env

# 2) узнай chat_id: открой бота в Telegram и нажми Start, затем:
python3 bot.py whoami

# 3) проверь, что источники живы
python3 bot.py check

# 4) запусти
python3 bot.py run          # или ./run.sh
```

При первом запуске бот не вываливает бэклог: он помечает всё старое как
прочитанное и пишет «Бот подключён». Дальше присылает только новое.

## 2. Команды

| Команда | Что делает |
|---|---|
| `/status` | состояние, лимиты, источники, которые молчат |
| `/sources` | список источников и их здоровье |
| `/last` | последние 10 отправленных новостей |
| `/digest` | собрать и прислать прямо сейчас |
| `/pause`, `/resume` | пауза и возобновление |
| `/mute 2` | тишина 2 часа |
| `/help` | справка |

Кнопки под новостью: **👍 Полезно**, **👎 Не то**, **🔗 Источник**.
После оценки кнопки голосования уходят, а **🔗 Источник** остаётся —
карточку открывают снова, чтобы взять ссылку в пост. Ссылки Google News
разворачиваются в адрес самого издания, поэтому в тексте карточки лежит
нормальный url, а не редирект-блоб.

## 3. Живой режим и как это не спамит

Бот работает в два потока: основной держит Telegram (команды и кнопки отвечают
всегда), фоновый собирает источники. Сбор идёт на двух скоростях:

- **быстрая полоса** — около десятка источников, которые реально приносят
  новости первыми, опрашиваются каждые `fast_interval_seconds` (90 с);
- **полный обход** всех источников — каждые `fetch_interval_seconds` (15 мин).

Источник попадает в быструю полосу полем `"tier": "fast"` в `sources.json`.
Быстрая полоса дешёвая: запросы условные (ETag / Last-Modified), и неизменённая
лента отвечает `304` без тела.

Защита от спама — пять уровней:

1. **Решает редактор, а не эвристика.** С ключом DeepSeek новость без вердикта
   редактора не уходит никогда (`require_verdict`). Вердикт, вынесенный под
   прежней версией `editorial.md`, тоже не считается: новость переоценивается.
2. **Порог формата.** В ленту идёт только то, что набрало `min_score` (7) по
   шкале редактора с учётом подтверждений. Явный промах ниже `reject_below` (5)
   сразу уходит в `rejected`, а «почти» ждёт: его может поднять подтверждение.
3. **Бюджет.** `max_per_day` (10), `max_per_hour` (1) и `min_gap_minutes` (40).
   Пауза соблюдается и внутри одной пачки: два сообщения подряд не уйдут.
4. **Гейт свежести.** `max_age_hours` (6) проверяется в момент отбора, а не
   только при сборе. Новость, пролежавшая в очереди до устаревания, получает
   статус `stale` и не приходит никогда.
5. **Повторы.** Три ступени:
   - **сюжеты.** Записи группируются по общим именам собственным и близости
     заголовков в окне `corroboration_window_minutes` (6 ч). Имена переживают
     перевод, так что русский и английский пересказ попадают в один сюжет. Как
     только сюжет отправлен, остальные носители помечаются `duplicate`;
   - **сверка с отправленным** за `dedup_window_hours` (96 ч), без модели:
     повтор, только если ключ события у редактора или набор имён в заголовке не
     добавляет ничего нового к уже отправленному. «Gemini 3 Pro» и «Gemini 3 Flash»
     разными событиями остаются: у каждой стороны есть слово, которого нет у другой;
   - **проверка редактором** для тех, кто может уйти следующим: кандидат
     сравнивается со списком отправленного за 96 ч. Реакции, мнения и пересказы
     того же события — повтор; новый крупный факт (слух стал релизом) — нет.
     Вопрос задаётся в фоновом потоке сбора, ответ хранится до следующей отправки.
     Поток Telegram к модели не ходит, так что кнопки и команды не зависают, даже
     когда API тормозит. После каждой отправки кандидат ждёт свежего ответа — до
     одного цикла быстрой полосы (90 с).

   Новость, на которой судья стабильно падает (кривой JSON, 4xx), после
   `llm_item_max_failures` (2) попыток пропускается и не мешает оценивать остальные.
   Сетевые сбои новость не штрафуют.

**Важное приходит сразу.** Отдельная полоса: `breaking_max_per_day` (3),
`breaking_max_per_hour`, своя пауза `breaking_min_gap_minutes`. Попасть в неё можно так:

- **сюжет дня** — оценка редактора не ниже `breaking_score` (9);
- **подтверждённое** — оценка не ниже `breaking_corroborated_score` (8), и сюжет
  уже несут `breaking_min_groups` (3) независимые группы источников или о нём
  написал канал-ориентир.

Если срочная полоса исчерпана, новость конкурирует за обычный слот. Устаревшее и
недатированное в срочное не попадает никогда.

## 4. Как отбираются новости

Двухступенчатый отбор — это главное решение архитектуры:

```
сбор (50+ источников, две скорости, условные запросы)
  → дедуп по каноническому URL (utm-хвосты не создают дублей)
  → группировка в сюжеты  ← имена собственные + близость заголовков, окно 6 ч
  → посты каналов-ориентиров — только сигнал для сюжета (status=signal)
  → дешёвый эвристический скоринг  ← бесплатно, по всем записям
  → шортлист (llm_min_heuristic и llm_max_per_cycle)
  → редактор DeepSeek по editorial.md: fit 0–10, рубрика, почему, черновик поста
  → + бонусы: независимые группы источников, канал-ориентир уже написал
  → гейт свежести → сверка с отправленным за 96 ч → бюджет / срочное
  → проверка повтора редактором → доставка + кнопки оценки
```

Почему так: эвристика бесплатна и работает по всем записям, а модель вызывается
только там, где эвристика уже видит потенциал.

Скоринг учитывает: вес источника, свежесть, слова-сигналы (релиз, прорыв,
покупка), сущности (OpenAI, Anthropic, DeepSeek, Qwen…), вовлечённость
(лайки, очки HN, апвоты HF, звёзды GitHub) и штрафы за рекламу, вакансии,
вебинары, мемы.

### Редакционный профиль: `editorial.md`

Главный вопрос бота — подошла бы эта новость каналам-ориентирам @codecamp и
@data_secrets. Профиль собран по разбору всех их постов за 26.06–13.09.2026
(681 пост) и лежит в `editorial.md`: читатель, рубрики с долями по каналам, что
каналы не берут, реальные посты как примеры, примеры «не формата» и стиль
черновика для каждого канала. Файл целиком уходит в системный промпт и правится
руками. Хэш промпта и профиля входит в ключ кэша и в сам вердикт, так что после
правки ожидающие новости переоцениваются сами — чистить таблицы не нужно.

Рубрики: `release`, `tool`, `breakthrough`, `viral`, `industry`, `safety`,
`outage`, `hardware`, `career`.

Карточка отвечает на вопрос «брать ли» до открытия ссылки:

```
🛠 Пу-пу-пу: агент больше не снесёт тебе систему — coop даёт ему одноразовую VM 🛡

Ночное-полезное: на HN показали coop — одноразовые виртуалки для Claude Code
и Codex. Агент получает Docker, git и терминал, но живёт в песочнице. Опенсорс,
лицензия MIT. Забираем, пока агент снова не решил «прибраться» 😅

🎯 7/10 · Полезное · в духе @codecamp
почему: опенсорсный инструмент, который решает боль каждого, кто боится пускать агента на свою машину
📣 уже написали: @codecamp · 🔁 источников: 3
hn_show · 40м назад
https://…
```

Спросить редактора про любой заголовок, ничего не отправляя:

```bash
python3 bot.py judge "Show HN: coop – disposable VMs for Claude Code and Codex" \
  --summary "coop spins up throwaway VMs for coding agents…" --source hn_show --group community
```

Замер на реальных заголовках (13.09.2026):

| Заголовок | Вердикт редактора |
|---|---|
| Yemeni militants used Anthropic AI to try to build ballistic missiles | 1/10, `skip`: люди и оружие, ИИ лишь упомянут |
| Show HN: coop – disposable VMs that sandbox Claude Code and Codex | 7/10, `send`, tool, в духе @codecamp |

### Каналы-ориентиры как сигнал

`tg_codecamp` и `tg_data_secrets` помечены в `sources.json` как `"role": "reference"`.
Их посты не отправляются — эти каналы ты и так читаешь, — а подтверждают сюжет. Если
канал-ориентир написал о том же, новость получает `reference_bonus` (+1), в карточке
появляется «📣 уже написали», а сильная (от 8) может уйти срочной.

### Предфильтр `interests`

`config.json` → `interests.suppress` / `boost` — дешёвый предфильтр по подстрокам.
Срабатывает до модели и не даёт нежеланным темам съедать бюджет LLM. Совпадение
подстрокой, без регулярок: `"ракет"` ловит ракета/ракеты/ракетных. Штраф
`suppress_penalty` (3.0) и бонус `boost_bonus` (0.8). Всё, что подстроки не умеют
(отличить релиз лаборатории от военного сюжета, где модель лишь упомянута),
решает редактор по `editorial.md`.

**Обучение на оценках.** Каждое 👍/👎 сдвигает вес источника и вес ключевых
терминов этой новости. Через пару недель отбор заметно смещается в твою сторону.
Посмотреть накопленное: `python3 bot.py stats`.

## 5. X / Twitter: что работает на самом деле

X — самый дорогой источник: официальный API с февраля 2026 полностью
pay-per-use, бесплатного тира нет. Ни один канал ниже не требует аккаунта,
cookies или сессионных токенов.

**Канал 1 — майнер ссылок из Telegram (`x_miner`).** Самый дешёвый: ссылки на
посты X лежат в уже скачанных страницах Telegram-каналов, то есть запросов к X
на обнаружение — ноль. Пост гидратируется слоем контента и попадает в общий
отбор. Работает.

**Канал 2 — Bluesky (`bsky_*`).** Не обход X, а легальная замена для тех, кто
там дублируется: `karpathy`, `emollick`, `natolambert`, `arankomatsuzaki`, плюс
официальные аккаунты theverge.com, techcrunch.com, microsoft.com, github.com.
Публичный API AT Protocol бесплатный, без ключей. Работает.

**Канал 3 — зеркала (`x_user`).** Здесь остался ровно один маршрут:
`rss.xcancel.com`. Проверено вживую 11.09.2026:

| Маршрут | Что реально отдаёт |
|---|---|
| `rss.xcancel.com` | валидный RSS — но требует whitelist читалки |
| `twiiit.com` | редирект на случайное зеркало → HTML-заглушка, 403/404 |
| `nitter.privacyredirect.com` | TLS-ошибка протокола |
| `nitter.tiekoetter.com` | HTML вместо фида |
| `nitter.net` | таймаут TLS-хендшейка |

Проверены и остальные публичные зеркала: `poast`, `space`, `lightbrd`,
`kareem.one` — все за Cloudflare; `rsshub.app/twitter/...` — 404.

Мёртвые четыре маршрута **удалены, а не оставлены про запас**: каждый вызов
`x_user` стоил 31,6 секунды на аккаунт и возвращал ноль записей — больше
половины всего цикла сбора на четырёх аккаунтах. Cooldown их не спасал: он
срабатывает по коду ответа, а зеркало, отдающее HTML с кодом 200, под него не
попадает и опрашивается каждый цикл заново. Возвращать маршрут — только после
того, как его увидели работающим.

**Как включить xcancel.** Фид отвечает `200` с текстом «RSS reader not yet
whitelisted» и выдаёт ID. Нужно одно письмо на `rss@xcancel.com` с этим ID
**и причиной** — запрос без причины игнорируется, фид предупреждает об этом
прямым текстом. Готовое письмо лежит в `~/.config/newsbot/xcancel-whitelist.eml`,
отправка — `~/.config/newsbot/send-xcancel.sh`.

⚠️ **ID привязан к User-Agent.** Другой UA — другой ID, whitelist перестаёт
действовать. Не менять `FEED_READER_UA` в `newsbot/x_sources.py`.

**Слой контента (по ID поста) — решённая задача:** `cdn.syndication.twimg.com`
(собственный embed-бэкенд X) → `api.fxtwitter.com` → `api.vxtwitter.com`.
Работает независимо от того, каким каналом найден ID.

Проверено и отвергнуто: `api.fxtwitter.com/<handle>` отдаёт только профиль, без
последнего поста — как канал обнаружения не годится.

Если xcancel тоже ляжет, остаётся официальный API: ~$0.005 за чтение поста, для
4–10 аккаунтов с опросом по `since_id` это порядка $5–10 в месяц.

Никаких аккаунтов, cookies, прокси и пулов сессий — принципиально: именно за это
X судится с зеркалами, и именно на этом банят аккаунты.

## 6. DeepSeek

```bash
python3 bot.py models    # список id моделей для твоего ключа
python3 bot.py stats     # расход токенов за сегодня
```

Модель и базовая URL берутся из `DEEPSEEK_MODEL` / `DEEPSEEK_BASE_URL`.
`thinking` отключён — для классификации это лишние деньги.

Экономика. Замер 13.09.2026 на 761 реальной записи: один вердикт редактора — около
4,4 тыс. входных и 150 выходных токенов. Входных почти вчетверо больше, чем у прежнего
судьи, потому что в промпт идёт весь `editorial.md`. Выше порога эвристики к редактору
попадает до 140 записей в день (замер на расширенном сборе, живой обычно меньше), то есть
до ~0,6 млн входных токенов в сутки. Системный промпт одинаковый во всех вызовах, поэтому
под кэш префикса у провайдера попадает большая его часть. Проверка повторов стоит около
1 тыс. токенов и вызывается только перед отправкой — не больше полутора десятков раз в
день. Точную цену смотри по тарифу своего ключа: `python3 bot.py stats` показывает расход
за сегодня.

Без ключа бот работает на эвристике: без редактора, черновиков и проверки повторов
моделью. Порог `min_score` и бюджеты тогда применяются к эвристическому баллу.

## 7. Постоянная работа

### macOS (launchd) — уже установлено

Агент лежит в `~/Library/LaunchAgents/ai.newsbot.plist` и поднимает бота при
входе в систему, перезапуская его после падения.

```bash
launchctl load   ~/Library/LaunchAgents/ai.newsbot.plist   # включить
launchctl unload ~/Library/LaunchAgents/ai.newsbot.plist   # выключить
launchctl list | grep newsbot                              # статус
tail -f state/newsbot.err                                  # лог
```

`KeepAlive` настроен на `SuccessfulExit: false` — чистая остановка через
`unload` не приводит к бесконечному перезапуску, а падение приводит.

### Только cron (режим без кнопок)

Кнопки оценки требуют живого процесса (long polling), а живой режим — тем более:
`once` не держит быструю полосу. Если нужен именно cron, доставка работать будет,
но с задержкой в интервал крона:

```
*/20 * * * * cd /PATH/ai-news-bot && ./run-once.sh >> /tmp/newsbot.log 2>&1
```

## 8. Управление источниками

`sources.json` — просто JSON. Поля: `name`, `type`, `group`, `weight`,
`enabled`, `role`, плюс параметры типа (`url`, `channel`, `handle`, `limit`).

Типы: `rss`, `hn_front_page`, `hn_show`, `hf_daily_papers`,
`hf_trending_models`, `telegram_web`, `github_rising`, `x_user`, `x_miner`, `bsky_user`.

`github_rising` — молодые репозитории с GitHub: созданы за последние `days` дней и
набрали не меньше `min_stars` звёзд. Официальный поиск GitHub. Закрывает
рубрику «Полезное»: github.com — самый частый домен в ссылках @codecamp (64 поста
из 361), а другие источники бота такие находки не приносят.

Ключ не обязателен. С сервера GitHub отклоняет часть анонимных запросов из Python
(403 «rate limit exceeded», хотя счётчики в `/rate_limit` нетронуты), а `curl` с той
же машины в ту же минуту проходит. Поэтому без ключа отказ повторяется через `curl`.
Если не пройдёт и он, `/sources` покажет «нужен GITHUB_TOKEN» — тогда положи в `.env`
fine-grained токен без доступов (Settings → Developer settings → Fine-grained tokens,
«Public repositories» read-only). Запросы с ключом идут только через Python: в
аргументы `curl` ключ не попадает.

`"role": "reference"` — канал-ориентир: его посты не отправляются, а только
подтверждают сюжеты (см. раздел 4).

`"tier": "fast"` кладёт источник в быструю полосу (опрос раз в 90 с вместо
15 минут). Держи её короткой: это оправдано только для лент, которые реально
приносят новости первыми.

Добавил источник — проверь: `python3 bot.py check --source ИМЯ`.
Отключить: `"enabled": false`.

Reddit `r/LocalLLaMA` подключён: раньше его `.rss` отдавал пустой ответ, на
11.09.2026 отвечает нормально. `venturebeat_ai` отключён — HTTP 429 на каждом
запросе.

## 9. Диагностика

```bash
python3 bot.py check                    # что отвечает, что молчит
python3 bot.py stats                    # состояние, веса, расход LLM
python3 bot.py xdiag                    # маршруты обнаружения X + ID для вайтлисты
python3 bot.py explain "OpenAI released a new model" --source openai_news
python3 bot.py judge "OpenAI released a new model" --summary "…"  # вердикт редактора
python3 bot.py once --dry-run --top 15  # что БЫ отправилось (ничего не шлёт)
python3 bot.py test-send                # проверка доставки
python3 -m unittest discover -s tests   # тесты отбора, повторов и карточки
```

Частые проблемы:

- **Ничего не приходит.** Сначала посмотри `once --dry-run --top 15`: там видны
  fit, рубрика и причина для каждого кандидата. Если редактор режет то, что тебе
  нужно, правь `editorial.md` (рубрики, «не формат», примеры), а не порог. Порог
  `min_score` (7) снижай в последнюю очередь — именно он держит ленту короткой.
- **Пришёл повтор.** Проверь, есть ли у обоих вердиктов поле `event`: сверка без
  модели опирается на него. Окно сверки — `dedup_window_hours`.
- **`chat_id is unknown`.** Не нажал Start в боте; сделай `python3 bot.py whoami`.
- **Источник в «молчат».** Смотри `/status`. RSS-ленты ломаются редко, зеркала X —
  регулярно; это ожидаемо.
- **Токен утёк.** `@BotFather` → `/revoke` → новый токен в `.env`.
